# 用户故事分册：会话管理与 LLM 配置

需求基线索引（附录 e2e 映射、未覆盖豁免段）见 [user-stories.md](../user-stories.md)。
本册收录 EP-5 会话管理、EP-6 LLM 配置。

## EP-5 会话管理

### US-19 对话历史与切换

作为用户，我希望打开对话历史列表、按最近排序看到全部会话（含子会话树），点击即切换，
以便延续之前的工作。

验收标准：

1. 「对话历史」按钮打开下拉面板；空态显示「暂无对话历史」。
2. 列表项显示标题、相对时间、消息数；子会话带 `sub` 角标并可折叠展开。
3. 运行中的会话有流水灯（运行蓝/等待黄）；点击条目宿主收到 `loadConversation`/
   `openConversation`（按宿主视图模式）。
4. 切换会话时显示「正在加载对话...」遮罩，加载完成后展示历史消息。
5. （桌面端）侧栏对话列表头部为「搜索框 + 新对话」：搜索框按标题过滤当前活动工作
   目录的对话，计数显示「N / M 个对话」。
6. （桌面端）切换工作目录后超过 100ms 仍未取到列表才显示「加载中」，快速命中不闪
   转圈；取到列表前不显示「暂无对话」。
7. （桌面端）侧栏「关闭」与聊天视图顶栏关闭按钮走同一关闭入口：对话非 idle（查询 /
   压缩 / 后台任务 / 子代理 / 等待用户确认任一）时先弹确认框（自绘消息框），默认与取消都落在
   「取消」；确认后才中止运行并关闭，取消则不动。从未发消息的新建会话视为空闲、
   不问。
8. 从磁盘加载会话时按 `meta.json` 记录的模型身份（provider + model）恢复会话模型：
   身份仍有效即沿用；模型不在该 provider 的模型列表 / provider 已移除则回退默认模型
   （该 provider 的默认模型；provider 已移除时为 active provider 的默认模型）并把
   回退结果写回 `meta.json`；未记录身份时取 active provider 的默认模型、不回写。
9. 子会话树按「默认展开」规则呈现：当前选中对话的祖先链默认展开（保证选中项可见）；
   选中对话自身的直接子会话数达到 5 时不默认展开（批量委派的对话不把列表撑满，用户
   仍可手动展开）。默认展开只在用户尚未显式设置过该对话的展开状态时生效；用户显式
   设置后，列表数据刷新不再改写它。该阈值是单一来源，webview 对话树与 Electron 侧栏
   共用。

### US-20 新建对话

作为用户，我希望一键新建对话并保留输入框里未发送的草稿，以便随手开新话题不丢内容。

验收标准：

1. 顶栏「新对话」按钮（桌面端为侧栏「+ 新对话」）触发新会话，未发送草稿被暂存。
2. 新会话的会话配置（模型/模式等）重置为 settings 默认值。

### US-21 重命名与智能命名

作为用户，我希望手动重命名对话，或让助手根据对话内容生成标题，以便历史列表可读。

验收标准：

1. 会话条目 hover 出「重命名」，行内输入 Enter 提交、Esc 取消；宿主收到
   `renameConversation`。
2. 「智能命名」发起后条目显示命名中状态，完成后标题刷新（`smartNamingResult`）。

### US-22 删除对话

作为用户，我希望删除不需要的对话（含其子会话），并有二次确认防误删。

验收标准：

1. 删除按钮弹出确认框「确定要删除 "..." 吗？」，确认后宿主收到 `deleteConversation`。
2. 删除当前打开的会话后视图切换到新对话（或按宿主模式关闭视图）。

## EP-6 LLM 配置

### US-23 管理服务商与模型

作为用户，我希望在设置页管理多个 OpenAI 兼容/Anthropic/Responses 服务商与各自模型
列表，以便在不同模型间切换。

验收标准：

1. 设置页以覆盖层打开（保留对话与草稿）；Provider 标签页支持新增、删除、双击设为
   当前使用。
2. 每个服务商配置 API 地址、API Key、模型列表；API Key 默认掩码，可切换明文显示
   （仅展示开关，不改保存内容）；模型行以「设为默认」按钮设默认（当前默认模型在模型名
   输入框内标注「(默认)」）、可删除、选择 API 协议（Responses/Completion/Anthropic）、
   打开「设置」弹层。
3. 「自动获取」从服务商拉取模型列表；未探测协议的模型弹自动检测确认（用户可跳过）。
4. 保存前校验：地址非空、不重复、至少一个服务商且各有模型、弹层限值为正整数；保存后
   宿主收到 `saveLLMConfig`，成功后面板关闭。
5. 模型行「设置」弹层配置三项（specs/013-model-settings-popup）：「多模态」开关（默认
   勾选，随配置持久化）、context 与 output 大小（正整数 token 数，清空即移除显式值、
   回落内置注册表解析值；弹层显式值优先于已有配置）。取消勾选的模型发送 LLM
   请求时过滤全部图片内容（用户消息与工具结果，三种协议一致），会话落盘记录仍保留
   完整图片，换回多模态模型后历史图片重新随请求携带。

### US-24 默认设置、界面语言与界面字号

作为用户，我希望设置默认思考强度、询问模式、提示词模式、联网搜索、界面语言与界面
字号，以便新会话开箱即用。

验收标准：

1. 默认设置分区可调三项模式与联网搜索（WebSearch / WebFetch 工具注入的默认值）；界面语言支持 自动/中文/English；界面字号
   档位 中 / 大 / 特大（默认中，相对基准 +0/+2/+4 像素）。
2. 保存后语言立即生效（界面整体重挂载为新语言）。
3. 界面字号随保存提交，宿主注入档位后即时生效：输入框、消息、菜单、设置面板与
   标题的字号统一随档位偏移，无需重启。
4. 默认服务商、当前对话所用服务商的默认模型、提示词模式、思考强度、询问模式、联网
   搜索、MCP 启用列表中任一项相对保存前有变化、且与当前对话的值不一致时，弹确认框
   询问是否应用到当前对话；确认后当前对话随之更新，取消则只改新对话默认值、不动
   当前对话。
5. MCP 全局默认启用列表的变更不自动改当前对话：保存时先把当前对话钉在它当前的列表
   上，取消后该对话的启用状态与保存前一致。
6. 钉住失败（读会话 MCP 事实失败）不阻断保存：全局默认值照常落盘，界面给出一条提示，
   不弹确认框。

### US-25 对话空间管理

作为用户，我希望统计并清理各工作目录占用的对话存储空间，以便控制磁盘占用。

验收标准：

1. 「统计」列出每个空间的路径、大小、文件数与对话数。
2. 每个空间两个操作，均需确认：「清除历史」清空对话数据、保留空间目录；「移除」
   删除整个空间目录（含工作目录相关配置），弹窗告知**不会影响工作目录本身**。两者
   宿主均收到 `clearConversationSpace`（`mode` 取 `clear` / `remove` 区分深度）。
3. 清理完成（或失败）后面板收到 `conversationSpaceCleared` 回执并解除「删除中」、
   刷新统计；删除期间按钮不得永久停留在「删除中」。
4. 统计发现「项目目录已不存在」的空间时弹提示列出全部缺失路径（目录多时列表自身
   滚动、按钮固定在滚动区外始终可点）；确认后按移除语义直接清理（不再二次弹窗）并
   刷新统计，列表不再显示这些目录；取消则仅展示统计。

### US-26 未保存关闭确认

作为用户，修改了配置但误点关闭时，希望被询问是否放弃修改，以免丢配置。

验收标准：

1. 有脏改动时点关闭/取消弹「放弃修改？」对话框，可选继续编辑或放弃修改。
