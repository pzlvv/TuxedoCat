# TuxedoCat 用户故事（US）

本文档描述 TuxedoCat 当前实现（as-built）面向用户的能力，以用户故事（User Story）形式
组织，作为场景级 UI 测试（`e2e/`）的需求基线：每条故事附验收标准，可验证的条目在
`e2e/webview/` 与 `e2e/electron/` 的用例中以 `US-xx` 编号引用。

- 架构与事件词汇的权威来源是 `DEVELOPMENT.md`；主题性规格见 `docs/<topic>.md`。
- 故事按主题（Epic）分组，编号规则：`US-<序号>`，全文唯一。
- 宿主双形态：VS Code 扩展（单视图）与 Electron 桌面端（多视图）。故事默认两种宿主
  都适用，仅桌面端适用的标注「桌面端」。

## EP-1 对话核心

### US-1 发送消息并获得流式回复

作为用户，我在输入框输入文字并按 Enter（或点击发送按钮），希望消息立即上屏、助手回复
以流式方式逐字呈现，以便我尽早读到答案。

验收标准：

1. 输入框为空或只有空白时发送按钮不可用；有内容时可用。
2. Enter 发送、Shift+Enter 换行；输入法合成状态下的 Enter 不触发发送。
3. 发送后用户消息立即出现在消息区，助手回复按增量渲染（流式期间有思考动画兜底）。
4. 助手回复支持 Markdown（GFM、数学公式），fenced 代码块带语言高亮。
5. 流式结束后回复固定为完整 Markdown 渲染结果。

### US-2 中止进行中的回复

作为用户，当助手回答跑偏或我改变了主意，我希望点「终止」按钮立即停止本轮查询，以便
省下时间和 token。

验收标准：

1. 会话空闲时终止按钮不出现/不可用；查询进行中才可点。
2. 点击后宿主收到 `abort`（携带会话 ID），本轮查询结束、界面回到空闲态。
3. 中止时若该会话有排队中的消息，排队内容回填到输入框供编辑重发。

### US-3 消息排队

作为用户，当助手正在处理上一条消息时我又输入了新消息，希望新消息排队并在本轮结束后
自动继续，以便我不用干等。

验收标准：

1. 引擎忙碌时发送的消息以「等待中」横幅显示（含图片数量提示），并可按提示重新提交修改。
2. 本轮结束后排队消息自动作为下一轮输入提交。
3. 用户主动中止时排队消息不提交，回填输入框。

### US-4 查看思考过程与流式统计

作为用户，我希望折叠查看助手的 thinking 内容与流式性能统计（首字耗时、解码速率），
以便判断回答质量与耗时。

验收标准：

1. thinking 内容渲染为可折叠区块（默认收起），标题含 `thinking` 字样。
2. 流式期间统计按字符计（chars），结束后按 token（tok）显示。
3. 无思考内容的回复不显示该区块。

### US-5 输入历史与斜杠命令补全

作为用户，我希望输入框为空时按 ↑/↓ 翻阅我发过的历史命令、输入 `/` 时弹出技能/命令
补全，以便快速复用。

验收标准：

1. 历史按会话保存，最多 50 条；↓ 退到底后恢复未发送的草稿。
2. 输入 `/` 弹出列表，↑/↓（或 Ctrl+N/P）移动、Enter/Tab 选中、Esc 关闭。
3. 内置命令带 `cmd` 角标；选中后替换 `/命令` 前缀、保留其余文本。

### US-6 粘贴图片发送

作为用户，我希望直接在输入框 Ctrl+V 粘贴截图一起发送，并在发送前可移除，以便描述
界面问题。

验收标准：

1. 粘贴后显示缩略图，缩略图右上角 hover 出移除按钮（`移除图片`）。
2. 发送时消息携带图片；排队/回填时图片数量被保留。

### US-7 未配置服务商时的引导

作为用户，首次使用尚未配置任何模型服务时，我希望输入区直接引导我去设置页，而不是
让发送静默失败。

验收标准：

1. 未完成 provider 配置时输入框禁用，占位层提示「点击设置」打开配置面板。
2. 配置完成并保存后输入框恢复可用。

## EP-2 输入区与会话配置

### US-8 功能开关菜单

作为用户，我希望在输入区一个菜单里集中切换模型、联网搜索、MCP、提示词模式、询问
模式与思考强度，以便不动离开对话流。

验收标准：

1. 菜单项顺序：设置、Spin 设计、联网搜索、MCP、模型、提示词模式、询问模式、思考强度。
2. 模型为三级子菜单（服务商 → 模型），当前模型有选中标记；切换后宿主收到 `setModel`。
3. 询问模式（总是/关键/从不）、思考强度（关/低/高/最高）、提示词模式（普通/极简/混合）
   以分段控件呈现，切换后宿主收到对应 `setAgentMode` / `setThinkingMode` / `setPromptMode`。
4. 会话配置未就绪时菜单显示加载态，不显示猜测值。

### US-9 上下文用量与手动压缩

作为用户，我希望看到当前上下文 token 用量进度条，并点击它触发对话压缩，以便长对话
不让上下文爆掉。

验收标准：

1. 用量条显示 `used/total (K)`，颜色随占用率从绿到红。
2. 点击用量条宿主收到 `requestCompress`；压缩完成后进度条按新值刷新。

### US-10 当前文件引用开关

作为用户在编辑器选中文件发送消息时，我希望默认携带文件路径与选中行，并可一键切换
「文件信息不发给 LLM」，以便控制上下文内容。

验收标准：

1. 状态条显示文件 chip（文件名 + 行号区间），点击切换隐藏/恢复。
2. 隐藏状态下发送的消息不携带文件信息。

### US-11 余额与缓存命中率展示

作为用户，我希望在输入区状态条看到账户余额与缓存命中率的瞬时值，以便感知消耗。

验收标准：

1. 余额显示金额或「无限」；查询失败时清空显示。
2. 缓存命中率 tooltip 展示读取/创建/原始输入 token 明细。

## EP-3 消息呈现

### US-12 代码块复制

作为用户，我希望一键复制助手回复里的代码块并得到「已复制」反馈，以便粘到编辑器里。

验收标准：

1. hover 代码块右上角出现「复制」按钮；点击后写入剪贴板并变为「已复制」约 2 秒。

### US-13 Mermaid 图表预览

作为用户，助手回复里的 mermaid 代码块我希望就地转成图表预览，以便直读流程图。

验收标准：

1. `language-mermaid` 代码块带「预览」按钮，点击后宿主收到 `openMermaidPreview`。

### US-14 工具调用卡片

作为用户，我希望每一步工具调用（Bash/读/写/编辑/搜索/子代理…）以卡片形式展示关键
参数与输出，以便审查助手做了什么。

验收标准：

1. 卡片显示工具图标、名称与参数摘要；Bash 卡片命令可复制、可查看完整命令与输出。
2. Edit/Write 卡片内嵌 diff/内容预览（红删绿增、单词级高亮），可展开/收起；超大输出
   持久化后显示「完整输出」按钮。
3. Read 卡片路径可点击打开文件；子代理卡片可点击跳转到子会话。

### US-15 回滚编辑

作为用户，我希望对某次 Edit/Write 直接「回滚修改到此」，并在确认框里选择回滚到修改
前还是修改后，以便撤销助手的文件改动。

验收标准：

1. 卡片上的回滚按钮弹出居中确认框，二选一（修改前/修改后）+ 取消。
2. 确认后宿主收到 `rollbackEdit`（含 toolUseId、文件路径、方向）。

### US-16 长消息折叠与用户消息置顶

作为用户浏览长对话时，我希望超长消息默认折叠、真正的用户消息滚出视口时吸附置顶，
以便快速定位上下文。

验收标准：

1. 超长用户消息显示「显示完整内容/收起」切换。
2. 用户消息滚动到顶时吸附为整宽条（`data-pinned`），点击空白处跳回原位。

### US-17 压缩历史展开

作为用户，对话被压缩后我希望展开压缩前的历史，以便回看被摘要替代的原文。

验收标准：

1. 存在压缩归档时消息区顶部出现「展开压缩的对话历史」按钮。
2. 点击后宿主收到 `expandCompact`，返回后整批消息替换显示，压缩摘要带虚线框标识。

## EP-4 权限与用户确认

### US-18 工具执行前的权限确认

作为用户，我希望危险或写操作在执行前弹确认让我放行或拒绝，以便掌控助手对工作区的
改动。

验收标准：

1. 权限请求以 `UserChoiceOverlay` 替换主输入框原位渲染：消息文本 + 选项按钮 + 文本
   输入框。
2. 点击选项或按数字键 1-9 直接选择；也可输入自定义文本回复后提交。
3. 提交后宿主收到 `respondUserChoice`（choiceId + index/reply），输入框恢复原草稿。
4. 「询问模式 = 总是」时所有工具都确认；「从不」时不打断（模型自行决策）。

## EP-5 会话管理

### US-19 对话历史与切换

作为用户，我希望打开对话历史列表、按最近排序看到全部会话（含子会话树），点击即切换，
以便延续之前的工作。

验收标准：

1. 「对话历史」按钮打开下拉面板；空态显示「暂无对话历史」。
2. 列表项显示标题、相对时间、消息数；子会话带 `sub` 角标并可折叠展开。
3. 运行中的会话有流水灯（运行蓝/等待黄）；点击条目宿主收到 `loadConversation`/
   `openConversation`（按宿主视图模式）。
4. 切换会话时显示「正在加载对话...」遮罩，加载完成后展示历史消息。

### US-20 新建对话

作为用户，我希望一键新建对话并保留输入框里未发送的草稿，以便随手开新话题不丢内容。

验收标准：

1. 顶栏「新对话」按钮（桌面端为侧栏「+ 新对话」）触发新会话，未发送草稿被暂存。
2. 新会话的会话配置（模型/模式等）重置为 settings 默认值。

### US-21 重命名与智能命名

作为用户，我希望手动重命名对话，或让助手根据对话内容生成标题，以便历史列表可读。

验收标准：

1. 会话条目 hover 出「重命名」，行内输入 Enter 提交、Esc 取消；宿主收到
   `renameConversation`。
2. 「智能命名」发起后条目显示命名中状态，完成后标题刷新（`smartNamingResult`）。

### US-22 删除对话

作为用户，我希望删除不需要的对话（含其子会话），并有二次确认防误删。

验收标准：

1. 删除按钮弹出确认框「确定要删除 "..." 吗？」，确认后宿主收到 `deleteConversation`。
2. 删除当前打开的会话后视图切换到新对话（或按宿主模式关闭视图）。

## EP-6 LLM 配置

### US-23 管理服务商与模型

作为用户，我希望在设置页管理多个 OpenAI 兼容/Anthropic/Responses 服务商与各自模型
列表，以便在不同模型间切换。

验收标准：

1. 设置页以覆盖层打开（保留对话与草稿）；Provider 标签页支持新增、删除、双击设为
   当前使用。
2. 每个服务商配置 API 地址、API Key、模型列表；模型行可设默认、删除、选择 API 协议
   （Responses/Completion/Anthropic）。
3. 「自动获取」从服务商拉取模型列表；未探测协议的模型弹自动检测确认（用户可跳过）。
4. 保存前校验：地址非空、不重复、至少一个服务商且各有模型；保存后宿主收到
   `saveLLMConfig`，成功后面板关闭。

### US-24 默认设置与界面语言

作为用户，我希望设置默认思考强度、询问模式、提示词模式、联网搜索与界面语言，以便
新会话开箱即用。

验收标准：

1. 默认设置分区可调三项模式与联网搜索；界面语言支持 自动/中文/English。
2. 保存后语言立即生效（界面整体重挂载为新语言）。

### US-25 对话空间管理

作为用户，我希望统计并清理各工作目录占用的对话存储空间，以便控制磁盘占用。

验收标准：

1. 「统计」列出每个空间的路径、大小、文件数与对话数。
2. 「删除」每个空间有清空确认，确认后宿主收到 `clearConversationSpace`。

### US-26 未保存关闭确认

作为用户，修改了配置但误点关闭时，希望被询问是否放弃修改，以免丢配置。

验收标准：

1. 有脏改动时点关闭/取消弹「放弃修改？」对话框，可选继续编辑或放弃修改。

## EP-7 工具与技能

### US-27 斜杠命令与技能触发

作为用户，我希望用 `/技能名` 直接触发技能（含内置命令如 `/commit`、`/spin`），以便
把常用流程固化成一键操作。

验收标准：

1. 技能来自 bundled → 项目 `.tuxedo-cat/skills/` → 用户 `~/.tuxedo-cat/skills/`。
2. 内置命令不进 LLM 上下文，执行后 UI 收到 `commandDispatched` 做客户端动作
   （如 `/spin design` 打开设计器）。
3. 技能与内置命令同名时技能被忽略并给出 WARNING。

### US-28 工具执行与结果回填

作为用户，我希望助手执行工具（Bash/Read/Write/Edit/Grep/Glob/TodoWrite/子代理…）后
把结果带回下一轮推理，直到给出最终答复，以便一次指令完成多步任务。

验收标准：

1. 工具调用 → （按权限策略确认）→ 执行 → 结果作为 tool_result 回传 LLM → 循环直至
   最终文本，整轮以 `queryEnd` 结束。
2. 工具输出按卡片实时更新（流式输出、行数、耗时）。

### US-29 MCP 服务器开关

作为用户，我希望在功能菜单里逐个启用/禁用 MCP 服务器并看到连接状态，以便控制可用
的外部工具。

验收标准：

1. 菜单 MCP 分组每服务器一行开关；状态小字显示 连接中/N 个工具/连接失败。
2. 切换后宿主收到 `setMcpEnabled`，core 落盘并广播新状态。

## EP-8 桌面端窗口与标题栏（桌面端）

### US-30 完整模式与悬浮窗切换

作为用户，我希望在完整模式（侧栏 + 聊天）与窄悬浮窗之间一键切换，悬浮窗可置顶，
以便把助手钉在角落。

验收标准：

1. 标题栏模式按钮切换；未打开工作区时禁用切换。
2. 悬浮窗隐藏原生侧栏，对话列表改由 webview 顶栏渲染（运行期切换渲染方）。
3. 悬浮窗专属「总在最前」开关；窗口模式与置顶状态持久化，重启恢复。

### US-31 窗口控制与状态恢复

作为用户，我希望标题栏提供最小化/最大化/关闭、双击最大化，窗口位置尺寸记忆上次
状态，以便符合桌面使用习惯。

验收标准：

1. 最小化/最大化(还原)/关闭可用；悬浮窗下最小化进托盘。
2. 位置与尺寸按模式分别持久化并在下次启动恢复。

### US-32 主题切换

作为用户，我希望主题在 跟随系统/浅色/深色 间切换并立即生效，以便适配环境光。

验收标准：

1. 菜单「主题」单选切换，全部视图（标题栏/侧栏/聊天/预览）即时应用。
2. 跟随系统时系统主题变化即时传播。

### US-33 系统托盘与任务提醒

作为用户，最小化到托盘后希望后台任务完成时图标闪烁提醒，以便不错过结果。

验收标准：

1. 托盘图标状态点：绿=全部空闲、红=运行中、黄=等待用户确认。
2. 后台任务完成且窗口不在前台时图标闪烁；任意窗口聚焦后停止。
3. 右键菜单「显示 / 退出」；左键唤出主窗口。

### US-34 全局唤醒快捷键

作为用户，我希望全局快捷键（默认 Ctrl+Alt+X）随时唤出或隐藏窗口并自动聚焦输入框，
并在设置对话框里改键，以便秒回对话。

验收标准：

1. 窗口不在前台按快捷键唤出并聚焦输入框；在前台再按隐藏回托盘。
2. 快捷键设置对话框捕获新组合（Esc 取消、Enter 保存），保存后立即生效并持久化。

## EP-9 多工作区（桌面端）

### US-35 打开与切换本地工作区

作为用户，我希望同时打开多个本地目录作为工作区，以标签页切换，每个工作区有独立的
对话与配置上下文。

验收标准：

1. 四个入口可打开本地目录（菜单 Ctrl+O、标签页 +、侧栏空态、聊天空态）。
2. 标签页显示目录名（远程带 `host:` 前缀）、活动项高亮、可关闭、可拖拽排序。
3. 切换工作区时聊天区切到该目录最近对话；关闭工作区销毁其对话视图并中止查询，磁盘
   数据保留。
4. 上次打开集合与活动项持久化，重启恢复；目录缺失的项保留并标红。

### US-36 打开远程工作区

作为用户，我希望粘贴连接串（`IP:端口#token`）或填 SSH 表单连接远端 Core，并在远端
目录选择器里选定目录作为远程工作区，以便操作远程机器。

验收标准：

1. 连接串/SSH 两步流：连接成功后立即弹出远端目录选择器（路径可编辑、前缀补全、
   新建/重命名/删除，删除有两阶段确认）。
2. 建链中标签页显示呼吸点；失败显示红点与聊天区占位页（带重新连接按钮）。
3. 远程工作区与本地工作区在标签页/侧栏/对话上同构。

### US-37 最近工作区

作为用户，我希望从「最近的工作区」快速重开常用目录，以便少点几次鼠标。

验收标准：

1. 最近列表上限 10；本地项过滤已不存在的目录；点击即打开或激活。

## EP-10 预览与 Spin（桌面端）

### US-38 文件与虚拟文档预览

作为用户，点击消息里的文件链接希望打开预览（Monaco 视图/只读内容模式，定位到选中
行），图片则用图片预览窗，以便不改上下文快速查看。

验收标准：

1. 文件链接打开 Monaco 窗口并定位行号；`showVirtualDocument` 以只读模式展示内容。
2. 图片走内置图片预览窗口。

### US-39 Spin 设计器

作为用户，我希望可视化编辑 `spin.json` 工作流并执行 `/spin` 流程，以便编排多步子代理
任务。

验收标准：

1. 输入区菜单「Spin 设计」或 `/spin design` 打开设计器窗口；已开则聚焦复用。
2. 保存写盘（队列防抖）与导出 JSON；执行完成后窗口数据自动刷新。

## EP-11 通知与国际化

### US-40 瞬时通知

作为用户，我希望系统级事件（保存结果、后台任务、错误）以顶部瞬时通知呈现并可手动
关闭，以便不打断对话流也不错过关键信息。

验收标准：

1. 通知按级别着色（info 蓝/warn 橙/error 红），info 5s、error 8s 自动消失，可点 × 关闭。

### US-41 界面语言

作为用户，我希望界面在中文与英文间切换（或跟随系统），以便用母语操作。

验收标准：

1. 语言跟随 设置值（auto 时按 VS Code/系统语言）或显式选择；切换立即生效于全部文案。
