# 任务分解：内置文本编辑器与 Markdown 预览的「变更」视图

执行顺序：git 取数与初始视图两个纯函数先落地（T001 / T002），Monaco 窗口的视图切换
（T003）与 Markdown 两组开关（T004）并行，宿主接线与非 git 探测（T005）收口；文档
（T006）、e2e（T007）、全量回归（T008）结尾。specs/041 与本 spec 共用 `electron/main.ts`
与侧栏接线，两个 spec 的宿主接线任务应同批实施、同一次提交。需求口径见 [spec.md](spec.md)，
技术方案见 [plan.md](plan.md)。

## 任务清单

- [x] **T001**（FR-001、FR-003、FR-004）：新增 `electron/gitFileContent.ts`——`FileContentRunner`（`showAtHead` / `hasHeadVersion` / `isClean`）与 `localFileContentRunner(root)`，三个方法都基于既有 `GitCommandRunner`（复用 `run(['show', 'HEAD:<rel>'])` / `run(['cat-file', '-e', 'HEAD:<rel>'])` / `run(['diff', '--quiet', 'HEAD', '--', rel])`，不新写 git 调用层），无 HEAD 版本返回 `null`、失败向上抛；模块纯 Node、不 import electron，并登记 `tsconfig.test.json` 的 `include`（单测直接 import）；依赖：—；完成判据：新增 `src/test/gitFileContent.test.ts` 用假 runner 覆盖 HEAD 有 / 无、clean / dirty、失败抛出，且三条命令参数逐字断言；`npm run test:unit -- git-file-content` 绿。
- [x] **T002**（FR-003）：`electron/fileOpen.ts` 新增纯函数 `resolveInitialView(source: OpenSource, isNewFile: boolean): 'full' | 'changes'`（`tree` 恒 `full`；`changes` / `toolLink` 且新增 → `full`，非新增 → `changes`），`openLocalWorkspaceFile` / `openRemoteWorkspaceFile` 增加 `source` 参数并在需要时用 `FileContentRunner.hasHeadVersion` 判定「新增」（判定只在主进程做一次，不复用 webview 缓存）；依赖：T001；完成判据：`src/test/fileOpen.test.ts` 补 `resolveInitialView` 六个组合与「新增判据接线」用例，既有分流用例全绿；`npm run check-types && npm run test:unit -- file-open` 绿。
- [x] **T003**（FR-001、FR-002）：Monaco 文本窗口——`electron/monaco/main.ts` 的 `MonacoInitData` 增加 `pathspec` / `hasHeadVersion` / `canDiff`，标题栏加「全文 / 变更」切换按钮（标签是切换目标、`aria-pressed` 表示当前是否在变更视图），`view` ↔ `diff` 复用同一窗口与 `filePath`、只重建编辑器实例，`viewState` 用 `Map<'view' | 'diff', …>` 各存一份，`isClean === true` 时不创建 `DiffEditor` 而显示「没有改动」空态，`mode === 'content'` 时不渲染切换按钮；diff 内容由主进程在切换时按需下发（`monaco-request-diff`，`event.sender === win.webContents` 校验）；依赖：T001；完成判据：新增 `src/test/monacoDiff.test.ts` 锁定 `buildDiffPayload({before, after})` 的 `diff` / `empty` 两态与「无 HEAD 版本时原文侧为空」；`npm run check-types:electron && npm run build:monaco` 绿。
- [x] **T004**（FR-002、FR-003）：Markdown 预览两组开关——`electron/monaco/markdownMain.ts` 把状态拆成正交的 `contentMode: 'rendered' | 'text'` 与新增 `sourceMode: 'full' | 'changes'`（渲染态忽略变更开关、切回文本时沿用变更取值），标题栏从左到右是新的「全文 / 变更」与既有的「渲染 / 文本」，变更态把编辑器容器换成同一个只读 `DiffEditor`（与 Monaco 窗口同一套配置，渲染实现只有一份），`markdown-init` 增加 `canDiff` / `hasHeadVersion`、`markdown-refresh` 在变更态改发 `{ before, after }`；初始视图 `initialSourceMode === 'changes'` 且非新增时直接落文本 + 变更（跳过渲染视图），`selectedLines` 定位仍落文本视图；依赖：T002、T003；完成判据：`npm run check-types:electron && npm run build:monaco` 绿，且 `electron/monaco/markdownMain.ts` 的两个状态字段与 `applyMode()` 的分支在源码里各自唯一（人工复核 + e2e 覆盖 AC-3 / AC-4）。
- [x] **T005**（FR-001、FR-003、FR-004）：宿主接线与非 git 工作区——`electron/ElectronUIHost.ts` 的 `openMonacoWindow` / `openMarkdownPreviewWindow` 扩展 init（`initialView` / `diffSource` / `canDiff`）并注册 `monaco-request-diff`；`electron/main.ts` 的三个打开来源传 `source`（文件树 `tree`、工具卡片链接 `toolLink`、「全部变更」视图 `changes` 由 specs/041 提供），远程工作区复用 `remoteGitRunner` 的 SSH exec 实现；`probeGitWorkspace` 结果塞进 `canDiff`，为 false 时按钮 `disabled` 且 `title` 写「不在 git 仓库内，无法显示变更」；依赖：T003、T004；完成判据：`npm run check-types:electron && npm run lint && npm run build:electron` 绿；`src/test/gitFileContent.test.ts` 的失败分支与 `src/test/fileOpen.test.ts` 的 `canDiff` 接线用例绿。
