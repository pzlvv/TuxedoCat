# 改动规格：会话交互增强——标签页右键菜单、空闲发送与跳到底部

本次改动补三组桌面端会话交互：Electron 工作区标签页的右键菜单（关闭 / 关闭所有空闲会话 /
关闭其它所有工作区 / 打开命令行）、输入区发送按钮的模式下拉（立即发送 / 空闲发送）、消息
列表非底部时的「跳到底部」按钮。前两组把分散的动作（标签 × 关闭、忙碌时自动排队）收拢为
显式入口，并新增「等会话空闲再发送」与两项批量关闭语义；第三组补齐长对话浏览后的回底操作。

## 用户场景与验收标准

验收标准一行式：GIVEN（前置）WHEN（动作）THEN（可观察结果），回指功能需求条目。
逐条可测，不写「支持 / 优化 / 合理 / 尽量」这类不可判定的词。

- 场景 1：标签页右键菜单（桌面端）
  - **AC-1**（FR-001）：GIVEN 已打开至少一张工作区标签 WHEN 在标签上右键 THEN 弹出原生菜单，含「关闭」「关闭所有空闲会话」「关闭其它所有工作区」「打开命令行」四项
  - **AC-2**（FR-001）：GIVEN 右键的工作区存在忙碌会话 WHEN 点「关闭」 THEN 先弹忙碌确认；确认后该工作区关闭（与点标签 × 同结果），取消则不动
  - **AC-3**（FR-001）：GIVEN 右键的工作区内存在空闲会话 WHEN 点「关闭所有空闲会话」 THEN 该工作区内空闲会话被关闭（当前选中的对话空闲也包含在内），其它工作区、忙碌会话与全部工作区标签保持不变
  - **AC-4**（FR-001）：GIVEN 多个工作区且其它工作区中存在忙碌会话 WHEN 点「关闭其它所有工作区」 THEN 弹一次汇总确认；确认后除右键标签外的全部工作区关闭，取消则全部不动
  - **AC-5**（FR-001）：GIVEN 远程（SSH）工作区标签 WHEN 右键弹出菜单 THEN「打开命令行」呈现置灰态、不可点
  - **AC-6**（FR-001）：GIVEN 本地工作区标签 WHEN 点「打开命令行」 THEN 在该工作区根目录按平台拉起系统终端
  - **AC-7**（FR-001）：GIVEN 只有一张工作区标签 / 右键的工作区内没有可关闭的空闲会话 WHEN 右键弹出菜单 THEN「关闭其它所有工作区」/「关闭所有空闲会话」对应置灰
- 场景 2：发送模式（立即 / 空闲）
  - **AC-8**（FR-002）：GIVEN 输入区有内容 WHEN 点主发送按钮 THEN 消息按既有立即发送语义提交（忙碌时登记排队项等下一轮、空闲时乐观回显直发），行为与本改动前一致
  - **AC-9**（FR-002）：GIVEN 输入区有内容 WHEN 点发送按钮旁的下拉箭头 THEN 菜单列出「立即发送」「空闲发送」两项；点「立即发送」的提交结果与主按钮一致
  - **AC-10**（FR-002）：GIVEN 会话忙碌 WHEN 以「空闲发送」提交 THEN 消息不进入本轮，横幅登记该项且标明「会话空闲后发送」
  - **AC-11**（FR-003）：GIVEN 空闲发送挂起项存在 WHEN 该会话的 `sessionBusyLevel` 变为 `idle` THEN 挂起项自动按立即发送语义提交、横幅清除
  - **AC-12**（FR-003）：GIVEN 空闲发送挂起项 WHEN 点横幅「编辑」 THEN 挂起项清除、内容（含选中的文件信息）回填输入框且不再提交
  - **AC-13**（FR-003）：GIVEN 空闲发送挂起项 WHEN 点横幅「删除」 THEN 挂起项清除、消息丢弃
  - **AC-14**（FR-003）：GIVEN 空闲发送挂起项 WHEN 该会话被关闭或释放 THEN 挂起项清除、不提交
  - **AC-15**（FR-003）：GIVEN 空闲发送挂起项存在 WHEN 用户中止该会话正在运行的查询 THEN 挂起项回填输入框、不自动提交
  - **AC-16**（FR-003）：GIVEN 空闲推送与带中止标记的 `queryEnd` 几乎同时到达 WHEN 二者都处置挂起项 THEN 中止回填生效（回填输入框、不投递），空闲触发对已清除的挂起项是 no-op
  - **AC-17**（FR-003）：GIVEN 空闲发送挂起项存在 WHEN webview 重载 THEN 挂起项丢失、不投递、不恢复
  - **AC-18**（FR-002）：GIVEN 无输入内容 / 连接或配置加载中 / 已有排队项（忙碌排队项或空闲挂起项） WHEN 渲染发送区 THEN 主按钮与下拉菜单项同样禁用（排队一次一条的既有约束不变）

## 功能需求

### FR-001：标签页右键菜单

Electron 多工作区标签页支持右键唤起菜单。菜单是宿主原生 OS 菜单（与点标签栏「+」弹出的
工作区菜单同形态），四项动作：

| 菜单项 | 行为 |
| --- | --- |
| 关闭 | 关闭右键标签对应的工作区，语义与点标签上的 × 完全一致：存在忙碌会话时先弹忙碌确认，取消则不动 |
| 关闭所有空闲会话 | 关闭**右键标签对应工作区**内判定为空闲的会话（当前选中的对话空闲也包含在内，关闭后由既有关闭入口切到相邻会话）：逐会话按判定时刻的会话运行时快照判定，空闲即关、忙碌（含等待用户输入）不动；其它工作区与工作区标签不受影响；不弹确认——空闲会话没有进行中的工作（判定后转忙的会话走既有逐会话忙碌确认，见边界与错误路径） |
| 关闭其它所有工作区 | 关闭除右键标签外的全部工作区；其中存在忙碌会话时先弹**一次**汇总确认（说明将关闭含进行中工作的会话），确认后全部关闭、取消则全部不动；无忙碌会话时直接关闭 |
| 打开命令行 | 在该工作区根目录按平台拉起系统终端，动作语义与侧栏文件树「在此处打开命令行」一致（detached、不随应用退出）；远程（SSH）工作区或目录已不存在时置灰 |

置灰规则：「打开命令行」在远程（SSH）或目录已不存在时置灰；「关闭其它所有工作区」在只有
一张标签时置灰；「关闭所有空闲会话」在右键工作区内没有空闲会话时置灰；「关闭」恒可用
（忙碌确认兜底）。菜单文案走宿主 i18n
（中英双语）。右键菜单不改变标签既有交互（左键切换、× 关闭、中键关闭、拖拽排序）。

### FR-002：发送模式下拉

发送按钮右侧新增下拉箭头（split button 形态），下拉菜单含「立即发送」「空闲发送」两项：

- **主按钮固定为立即发送**：行为与现状一致——提交用户消息，是否排队由引擎忙碌状态决定
  （[docs/features/user-message-pipeline.md](../../docs/features/user-message-pipeline.md) FR-001
  的既有语义不变）。
- 下拉两项均为**当次动作**：点选即以该模式提交当前输入，不记住选择、不改变主按钮语义。
  「立即发送」与主按钮等价；「空闲发送」见 FR-003。
- 禁用口径与主按钮一致：无内容 / 输入禁用 / 连接与配置加载中 / 已有排队项（忙碌排队项或
  空闲挂起项）时，主按钮与下拉项同样禁用。

### FR-003：空闲发送的挂起语义

「空闲发送」把提交时机推迟到会话完全空闲：

- **挂起是 webview 本地状态**：以「空闲发送」提交的消息暂不上送宿主、不进入引擎，由
  webview 以本地挂起项持有并按既有排队横幅形态呈现；`sendMessage` wire 类型与载荷、
  `onQueuedMessage` 登记口径均不变（[docs/architecture/contracts.md](../../docs/architecture/contracts.md)
  无 delta）。
- **空闲判定与既有排队判定同一事实源**：core 会话运行时快照派生的 `sessionBusyLevel`，
  `idle` 级别即无进行中查询、无等待用户输入、无压缩、无后台任务、无子代理。
- **挂起判定**：以「空闲发送」提交时，该会话快照**显式忙碌**（`idle === false`）才挂起；
  快照缺失（未登记的新会话等）视为本就空闲、等价立即发送——是否排队最终仍由宿主按
  引擎忙碌状态裁决，消息不因判定缺失而滞留（边界「会话本就空闲时提交」条的上界口径）。
- **触发**：该会话 `sessionBusyLevel` 变为 `idle` 时，挂起项自动按立即发送语义提交（走既有
  `sendMessage` 管线：此刻若会话又已忙碌，自然落入既有忙碌排队语义，不丢弃消息），横幅
  清除。
- **中止不投递**：用户中止该会话正在运行的查询时（`queryEnd` 带中止标记），挂起项不自动
  提交——回填输入框（与既有排队中止回填共用同一实现），等待用户确认。空闲推送与中止
  `queryEnd` 的竞态以中止回填收敛：回填先清除挂起项，空闲触发以「挂起项仍登记」为前提，
  对已清除项是 no-op。
- **撤回**：横幅「编辑」= 清除挂起项并把内容（含选中的文件信息）回填输入框（与既有排队
  撤回共用同一实现）；「删除」= 直接丢弃。撤回是 webview 本地动作，不经宿主。
- **清除**：会话关闭 / 释放时挂起项随之清除，不提交——回收依据运行时快照缺席：**非空**
  快照中不再包含该会话即视为已关闭 / 释放；空快照视为信息不足（启动期补拉），不回收、
  不触发。webview 重载（窗口刷新 / 重开）后挂起项丢失——不投递、不恢复（本地状态，
  无持久化）。
- 命令消息（`/` 开头）的空闲发送只延迟提交时机：命令解析仍发生在提交后的既有管线内，
  规则不变。空闲挂起项与忙碌排队项同为「一次一条」：任一存在期间发送区禁用（FR-002）。

### FR-004：跳到底部按钮

消息列表不在底部时（用户滚离底部、超出自动跟随容差），输入框上方浮现「跳到底部」按钮；
在底部时不显示。点击按钮：列表滚动到底部并恢复自动跟随（后续新消息恢复自动滚动），按钮
隐藏。会话切换 / 视图重建时按钮隐藏（新视图初始位于底部）。按钮是纯定位操作，不携带未读
计数等附加信息。按钮文案走 webview i18n（zh / en）。

## 边界与错误路径

- **远程工作区 / 目录已缺失的「打开命令行」**：置灰是终态（远程不做 SSH 远端终端，目录
  已不存在无从打开）；置灰在菜单呈现，不是点击后报错。
- **批量判定竞态**：「关闭所有空闲会话」逐会话按判定时刻的快照决定；判定后、关闭时已转忙
  的会话走既有逐会话忙碌确认（确认则关、取消则跳过该会话继续其余会话），不静默跳过；
  「关闭其它所有工作区」的汇总确认取消后全部不动，不存在部分关闭。
- **空闲发送提交竞态**：触发提交时会话已转忙碌 → 按既有忙碌排队语义登记排队项，消息不丢。
- **中止与空闲触发竞态**：中止回填优先，空闲触发对已回填清除的挂起项是 no-op（FR-003）。
- **webview 重载**：空闲挂起项丢失、不投递、不恢复（FR-003）。
- **空闲发送在会话本就空闲时提交**：等价立即发送（无需等待）。
- **下拉打开时输入被清空**：菜单项按与主按钮一致的禁用口径置灰，不产生空消息提交。
- **无工作区 / 无标签**：右键入口不存在，本节各行为不适用。
- **跳到底部按钮与折叠态**：按钮可见性只由「是否在底部」决定，与消息卡片折叠状态无关。

## 非目标

- 不做「记住上次发送模式」（主按钮恒立即发送）；不做多条挂起队列——排队一次一条的既有
  约束不变，连续多条靠「发出后再写下一条」。
- 跳到底部按钮不做未读计数 / 新消息提示徽标。
- 标签页右键菜单不做重命名 / 固定标签 / 拖出成新窗口等浏览器式扩展项。
- VS Code 宿主不引入标签页与右键菜单（无多工作区标签 UI）；「空闲发送」与「跳到底部」属
  webview 输入区 / 消息区行为，两宿主同享。
- 不改 VS Code 的自动空闲回收（`docs/hosts/vscode-idle-close.md` 的自动口径不动，Electron
  仍不自动回收）。

- **US-46 空闲发送**、**US-47 跳到底部**：webview 内交互，Playwright 可驱动，在附录映射表

  `src/test/` 单测覆盖，菜单弹出与置灰态人工验证。
