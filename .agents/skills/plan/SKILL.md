产物：`specs/<NNN>-<slug>/plan.md`。只做这一件事，产出即停等人评审。

**前置闸门（不过即拒绝，指出缺什么）**：

- `specs/<NNN>-<slug>/spec.md`（或 `defect.md`）存在，且用户已确认评审通过；
- spec 的「待澄清」节已清零（无 `[待澄清]` 残留——未决问题先转 ADR / 第 6 章 / 非目标）。

步骤：

1. 复制 `specs/_templates/plan.md` 到同一 spec 目录。
2. 技术方案：模块划分、数据流、关键类型 / 事件 / 契约形态；引用既有模块与规格章节。
3. 受影响模块与契约：逐文件列改动面；契约 / 事件变化点名成员。
4. 宪章检查逐条过并勾选（不过不进入实施）：分层与依赖、架构铁律、两套 Core parity
   义务（涉及任一侧 Core 必须同步另一侧 + 对照表 + 两侧测试）、文档同步义务；
   不适用的一条也写「不涉及 + 理由」。
5. 被否决的替代方案：逐个列路线与否决理由；够分量的决策提示用户进 `docs/adr/`。
6. 把 spec 的 status 改为「待评审」，停：交给用户评审。

规则出处：`specs/README.md`、`AGENTS.md` 第 1 / 4 / 5 节。
