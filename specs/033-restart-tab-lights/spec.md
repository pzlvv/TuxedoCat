# 改动规格：标签页流水灯改为对话灯的自动联动

灯状态收敛为两层、写入点归一到对话级：**对话行灯**（运行蓝 / 等待黄——core
`sessionRuntimeChanged` 全量快照的投影；未读完成绿——宿主武装集合的幂等全量快照）是唯一
显式维护的灯状态；**标题栏标签页灯**不再独立武装、独立聚合、按触发点补推，而是其内对话灯
的**自动联动投影**——任何使对话灯或会话归属变化的输入落定后，标签页灯立即等于最新聚合，
不再依赖「碰对触发点」。重启认领、列表晚到、归属索引晚到、静默在跑这四类反复出问题的
时序缺口由此从「逐个补重推」变成一般保证（缺陷
`restart-tab-lights-incomplete` / `orphan-completion-unread-light` 的场景转正为验收标准）。
已读消失语义保持：激活标签页灭标签页绿灯（行灯不动）、对话成为当前对话或回窗聚焦正看着
时灭行绿灯、会话消失 / 工作区关闭即灭、蓝黄无已读语义。随联动模型而来的三处定向行为差异
（绿灯跟随行灯启闭、激活后不再复亮、补武装落定后的可见性清理）在 FR 中逐条声明。

## 用户场景与验收标准

- 场景 1：对话灯武装与已读（既有语义，回归锁定）
  - **AC-1**（FR-005）：GIVEN 会话在用户看不到时完成（窗口失焦 / 标签页未激活 / 非当前对话任一命中）WHEN running → idle 迁移到达 THEN 对话行绿灯武装并即推——可见但未聚焦的窗口当场亮灯，呼吸一次后常亮
  - **AC-2**（FR-005）：GIVEN 对话行绿灯亮 WHEN 该对话成为当前对话 THEN 行绿灯熄灭，且此后列表刷新的旧计数不再重新武装（已读护栏对武装来源生效）
  - **AC-3**（FR-005）：GIVEN 对话行绿灯亮 WHEN 回窗聚焦且此刻完全可见（聚焦 + 激活标签页 + 当前对话）THEN 行绿灯在推送前熄灭，之后切到别的对话不补亮
  - **AC-4**（FR-005）：GIVEN agent 创建的会话（creator 为 agent 形态）完成 WHEN 在线差分或离场补武装到达 THEN 对话行与标签页都不亮
  - **AC-5**（FR-005）：GIVEN 离场完成的会话（meta.json `unreadCompletions` > 0）WHEN 对话列表装载 THEN 行绿灯补武装、标签页绿灯随归属解析联动点亮；打开该对话即清零并不再武装
- 场景 2：标签页灯自动联动
  - **AC-6**（FR-002）：GIVEN 标签页内任一会话非 idle WHEN 状态流推送到达 THEN 该标签页亮黄（等待优先）或蓝（运行），状态消失即灭——蓝黄无已读语义
  - **AC-7**（FR-001）：GIVEN 标签页内存在已武装未读的对话 WHEN 其武装时刻晚于该标签页最近一次被激活的时刻（含从未激活）THEN 标签页亮绿
  - **AC-8**（FR-002）：GIVEN 标签页绿灯亮 WHEN 用户激活该标签页 THEN 绿灯熄灭，该对话的行绿灯保持；再次切走切回不复亮
  - **AC-9**（FR-002）：GIVEN 激活中的标签页内非当前对话完成、用户没看到这次完成 WHEN 武装发生 THEN 行绿灯与标签页绿灯同时亮（联动）；切走再切回后标签页绿灯灭、行绿灯保持
  - **AC-10**（FR-002）：GIVEN 标签页绿灯亮 WHEN 该标签页内最后一个未读对话被阅读（成为当前对话 / 聚焦可见）THEN 标签页绿灯随之熄灭，无需切换标签页
  - **AC-11**（FR-002）：GIVEN 离场完成的会话补武装且归属可解析 WHEN 列表到达 THEN 标签页亮绿——重开激活中的标签页也算未读；此后激活过该标签页就不再复亮
- 场景 3：时序缺口消灭
  - **AC-12**（FR-003）：GIVEN 重启认领场景运行时快照早于对话列表到达 WHEN 列表到达、归属索引补齐 THEN 静默在跑任务的标签页蓝灯出现——不依赖后续状态推送
  - **AC-13**（FR-003）：GIVEN 会话归属索引晚到（非活动目录的列表后到）WHEN 归属解析落定 THEN 该会话的行灯与标签页灯随之出现，不需要下一次列表到达
  - **AC-14**（FR-003）：GIVEN 任一使灯状态变化的输入（状态快照、列表装载、归属解析、武装、已读、标签页开关）落定 WHEN 渲染层收到推送 THEN 标签页灯等于该时刻输入的最新聚合——不存在「输入已变、灯等下一次触发」的窗口
- 场景 4：渲染层零规则副本
  - **AC-15**（FR-004）：GIVEN 宿主推送的武装快照包含某会话 WHEN webview 对话列表 / 侧栏渲染 THEN 该行亮绿灯——渲染层不再以「当前对话」「子会话行」自判摘灯，子会话行不亮由宿主在推送集合保证
  - **AC-16**（FR-004）：GIVEN 标题栏收到工作区聚合推送 WHEN 渲染 THEN 按推送内容点亮三色灯条、不附加本地判定（现状已达成，回归锁定）

## 功能需求

### FR-001：灯状态分两层——对话灯显式、标签页灯联动

灯状态只有对话级一个写入层：

- 对话行的运行蓝 / 等待黄：core `sessionRuntimeChanged` 全量快照的投影（webview 对话列表
  与侧栏直接读状态流，现状不变）；
- 对话行的未读完成绿：宿主武装集合（`electron/completionAttention.ts` 的在线差分 + 离场
  补武装），以幂等全量快照推送给标题栏 / 侧栏 / webview；
- 标签页灯**不持有任何独立的状态集合、武装规则或补挂重试清单**：三色灯随时等于其内
  对话灯的聚合（定义见 FR-002）。「哪些行该亮」「哪些标签页该亮」只由宿主判定一份，
  渲染层只呈现。

### FR-002：标签页灯的聚合定义与已读基准

- 蓝 / 黄（忙闲）：标签页内任一会话 waiting → 黄（优先）；否则任一非 idle → 蓝。
  忙闲派生收敛在 core 的 `sessionBusyLevel`，与托盘 / 关闭确认同一份（语义不变）。
- 绿（未读完成）：标签页内存在「已武装且未读」的对话、且其**武装时刻晚于该标签页最近
  一次被激活的时刻**（从未激活视为最旧——任意武装都亮）→ 绿。武装时刻：在线差分取
  完成迁移时刻，离场补武装取列表装载时刻（必然晚于重开激活，天然满足「激活中的也算
  未读」）。
- 已读基准：激活标签页把该标签页的已读基准推进到当前时刻——绿灯立即熄灭，对话行绿灯
  不受影响；标签页关闭即丢弃其已读基准，重开按新标签页处理。
- 由联动模型产生的一处定向差异（有意的行为修订，非回归）：**绿灯跟随行灯启闭**——
  标签页内最后一个未读对话被阅读时绿灯随之熄灭（现状残留到下次激活才灭）；激活中的
  标签页内非当前对话完成时绿灯与行灯同时亮（现状标签页保持暗）。两处都是「标签页灯
  跟随对话灯」的直接结果，消除「行亮标签不亮」「行灭标签还亮」的联动断联。

### FR-003：联动即时性——时序缺口消灭

标签页灯是其输入（会话运行时快照、会话归属解析、武装集合、已读基准、打开集合）的纯
投影；**任一输入变化后，标签页灯即为最新值**，不要求新的状态推送 / 列表重读 / 重连 /
重开。已知四类时序缺口成为一般保证的验收场景，不再逐个补「重推一次」的触发点：

- 重启认领：运行时快照早于对话列表到达（daemon 在 openWorkspace 应答里就重放）；
- 归属索引晚到：非活动目录的列表后到，归属解析此前不命中；
- 静默在跑：工具执行期没有新的状态快照，聚合没有后继触发点；
- 离场补武装：`unreadCompletions` 随列表到达，归属可能仍缺。

### FR-004：渲染层零规则副本

标题栏、侧栏、webview 对话列表只呈现宿主推送的幂等全量快照，不携带点亮 / 熄灭规则：
「活动项不亮」（标题栏在 `restart-tab-lights-incomplete` 已摘，回归锁定）、「当前对话
不亮」「子会话行不亮」（webview 与侧栏的现存副本）一律摘除——这些规则由宿主保证：
子会话行不亮在武装 / 推送源头过滤，「正在看的就是已读」由已读清除（FR-005）保证。
呼吸动画、颜色、灯条样式等呈现细节不是规则，留在渲染层。

### FR-005：武装与已读语义（保持为主 + 两处归一）

武装语义不变：

- 在线差分：running → idle 且用户当时看不到（窗口失焦 / 标签页未激活 / 非当前对话任一
  命中）→ 武装对话行；武装即推（失焦也推）；waiting → idle 不算完成；新出现的会话只
  登记不武装。
- 离场补武装：meta.json `unreadCompletions` > 0 的会话随列表装载补武装，不适用在线的
  可见性规则（完成时刻用户完全缺席）；agent 创建的会话在两个武装源头都保持安静
  （specs/025 FR-003）。

已读清除语义不变（枚举）：

- 对话成为当前对话 → 该对话行绿灯灭；
- 回窗聚焦此刻完全可见（聚焦 + 激活标签页 + 当前对话）→ 行绿灯灭（聚焦即已读，切到
  别的对话不补亮）；
- 激活标签页 → 该标签页绿灯灭，行绿灯不动（已读基准语义见 FR-002）；
- 会话从快照消失 / 工作区关闭 → 相关行绿灯灭，标签页绿灯随联动消散；
- 打开对话 → core 侧 `unreadCompletions` 清零。

两处归一（修正现状缺口，非语义变更）：

- 已读护栏（`completionsReadInRun`）对**全部武装来源生效**：打开对话后，在途列表快照里
  的旧 `unreadCompletions` 计数不再重新武装（该护栏已先行落地，见
  [specs/defects/completion-tab-light-relights-after-read.md](../../specs/defects/completion-tab-light-relights-after-read.md)）；
- 补武装落定后宿主执行一次可见性清理：此刻正完全可见（聚焦 + 激活标签页 + 当前对话）
  的条目当场按已读处理——与在线武装的「聚焦即已读」同一口径，重开时用户正盯着的对话
  不亮灯。

## 边界与错误路径

- **归属解析不出**（跨工作区子代理会话等路由表兜底 / 索引未到）：行绿灯照常武装；
  标签页绿灯等归属落定后由联动自动出现——不丢、不假亮（路由表兜底语义不变）。
- **浮窗模式**：没有标签页区，标签页推送照发不亮（现状不变），切回完整模式补齐。
- **工作区不可用 / 建链中**：标签页存在、灯按输入照常聚合；可用性红黄点是另一套状态，
  不在本规格范围。
- **列表快照按工作区稳定 id 分份**（同路径不同主机的远程工作区互不命中）：归属解析
  与已读基准都按稳定 id，语义不变。
- **时钟单调性**：武装时刻与已读基准取同一进程内时钟；离场补武装的武装时刻是本进程的
  列表装载时刻，必然晚于重开激活，不受跨进程时钟影响。

## 非目标

- 不改 core 事件流与 wire 协议词汇：不新增事件，`sessionRuntimeChanged` / 列表请求 /
  既有推送通道维持。标题栏的忙闲推送与绿灯推送两条通道是否合并为一条由 plan 决定，
  不作为本规格的验收面。
- 托盘状态点、「任务结束」提醒闪烁与提示音、睡眠阻断、关闭确认的语义不变——它们
  消费同一份忙闲派生，但不是本规格的灯面。
- 对话行蓝 / 黄灯的呈现方式不变（webview / 侧栏对状态流的直接投影维持现状）。
- VS Code 宿主没有标签页灯与托盘，不涉及；其 webview 行灯投影不变（武装快照恒为空集）。
- 灯条的动画、颜色、呼吸时长等呈现细节不变。
