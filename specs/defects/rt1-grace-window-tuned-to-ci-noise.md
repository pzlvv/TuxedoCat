# 缺陷：RT-1 大帧用例把探针宽限压到调度噪声量级，CI 上偶发误判死

`src/test/remoteCoreDaemon.test.ts` 的「RT-1 大帧停顿期间心跳独立通路保活（不判死）」
注入 `silenceRecheckMs = 40`（探针宽限 40ms，配合死线 80ms 的判死预算 120ms）。用例与
假远端共用同一条事件循环，CI 上（2 核跑 4 个测试文件）进程被调度出去时，心跳 `pong`
在宽限内送不进来，宽限窗口整个被吃掉，看门狗就按契约判死——红在 CI 上，但判死逻辑本身
没有错，是用例把时间轴压到了调度噪声量级。

这条偶发红在
[`silence-recheck-runs-before-inbound-drain`](silence-recheck-runs-before-inbound-drain.md)
的 RT-3 里已被登记为「必须消失」，之后仍在 CI 上复发。

## 现状

- 注入参数（`src/test/remoteCoreDaemon.test.ts` 的「心跳独立通路：大帧传输期间不判死」段）：

  ```text 示意（宽限 40ms，判死预算 = 死线 80 + 宽限 40）
  const daemon = new CoreDaemon({
    heartbeatIntervalMs: 20,
    silenceDeadlineMs: 80,
    silenceRecheckMs: 40,
    ...
  ```

- 本地实测（探针，空闲机）：大帧开始后相邻两次心跳 `pong` 写出的最大间隔已达 **38ms**，
  而宽限只有 40ms——**余量约 2ms**。进程一旦被调度出去一个时间片，宽限窗口就被吃光。
- CI 现场：run `45544663383` 的 `tests` job（2 核 / 单测 4 路并发）：

  ```
  ok   RT-1 大帧用例完成握手
  ok   RT-1 心跳已往返（沉默判定武装）
  ok   RT-1 大帧开始下传（字节已流动，但没有完整帧）
  FAIL RT-1 大帧停顿期间心跳独立通路保活（不判死）
  ok   RT-1 心跳链路的 pong 独立往返
  ```

  注意「心跳链路的 pong 独立往返」仍是绿的：心跳通路当时是通的，被吃掉的是宽限窗口。
- 本地无法直接复现（12 路并发、6 核全忙循环、200+ 份压测均绿），偶发率低于本地可观测阈值。

## 期望

- 探针宽限必须显著大于被测环境的调度噪声：宽限的职责是吸收「本进程卡顿 / 字节积压在内核
  缓冲」（[core-remote.md 第 2.5 节](../../docs/core/core-remote.md#25-连接与生命周期)），
  压到与噪声同量级就不再是吸收，而是把噪声直接判成断连。
- 观察窗随之覆盖「死线 + 宽限」并留余量，使「心跳真被大帧饿死」仍落在窗内（灵敏度不降）。
- 断言要能区分「本缺陷的形态」与「任意 fatal」：只有沉默判死才算心跳被业务大帧拖垮。
- 产品侧判死逻辑、默认常数（1s / 9s / 900ms）与 `LINK_SILENCE_DEADLINE_BUDGET_MS` 一律不改。

## 不变量

- 产品行为不变：`CoreDaemon` 的沉默判定、探针、宽限收口、fatal 文案与 kill 位点都不改；
  本次只调用例注入的时间参数与观察窗。
- RT-2（慢速大帧按字节判活）与「宽限期内到达的 pong 不因收口早于入站入账被判死」两条
  用例的注入参数与断言不变，仍须绿。
- 灵敏度必须可证伪：武装判定之后把心跳链路的 `pong` 停掉（心跳被「饿死」的形态），
  「不判死」与「未以沉默判死收场」两条断言都要变红。

## 回归测试

- **RT-1**：注入宽限放宽到 250ms（约 6 倍于实测噪声），观察窗 600ms 覆盖「死线 + 宽限」，
  大帧停顿期间不得判死（落点：`src/test/remoteCoreDaemon.test.ts` 的
  `RT-1 大帧停顿期间心跳独立通路保活（不判死）`）。
- **RT-2**：判死原因收窄到本缺陷形态——`failure.error` 为空，或文案不含 `silent for`
  （落点：同上用例的 `RT-1 未以沉默判死收场`）。
- **RT-3**：灵敏度可证伪——武装后停掉心跳 `pong`，上述两条断言变红
  （落点：验证记录里的临时实验，不落仓库）。
